# WindAI Lab — 風力發電 AI 智慧運維平台

## 產品簡介

WindAI Lab 是一套專為風力發電場設計的 **AI 驅動智慧運維平台**，整合多種機器學習模型與多代理協作架構，協助風場業者從 SCADA 資料中自動發現異常、預測故障、管理工單，並持續累積維護知識，實現**從被動維修到主動預防**的轉型。

---

## 核心理念

```
傳統運維                              WindAI Lab 智慧運維
────────────                          ──────────────────
故障發生 → 人工發現 → 緊急搶修          持續監控 → AI 預警 → 計畫性維護
經驗依賴個人 → 人員離職經驗流失          知識自動沉澱 → 組織能力持續成長
單一報表 → 難以跨風場比較              多風場統一儀表板 → 全局最佳化
```

**一句話定位**：讓每一座風場都擁有一支 24 小時值班的 AI 工程師團隊。

## 系統功能

### 1. 智慧資料分析

| 功能 | 說明 | 價值 |
|------|------|------|
| **SCADA 自動清洗** | 自動偵測並處理異常值、缺失值、感測器故障資料 | 節省 70%+ 資料前處理時間 |
| **通用資料載入** | 支援 CSV、Parquet、Excel、ZIP 等格式，自動匹配 60+ 種欄位名稱 | 即插即用，無需手動對應欄位 |
| **風機參數自動推斷** | 從資料中自動推斷額定功率、切入/切出風速等參數 | 不需要手動輸入風機規格 |

### 2. AI 預測模型

平台內建多種經過驗證的機器學習模型，可依據資料特性自動選擇最適模型：

| 模型 | 技術 | 用途 | 已驗證效能 |
|------|------|------|-----------|
| **功率曲線正常行為模型 (NBM)** | Gradient Boosting | 偵測功率異常衰退 | R² = 0.9964 |
| **故障分類器** | XGBoost | 自動辨識故障類型 | F1 = 1.0000 |
| **剩餘壽命預測 (RUL)** | 退化建模 | 預測組件何時需要維修 | 趨勢分析驗證通過 |
| **LSTM 時序預測** | PyTorch LSTM | 風速/功率短期預測 | 支援自動降級至 Ridge AR |
| **PatchTST 時序預測** | Transformer | 捕捉長距離時序依賴 | 學術前沿架構 (ICLR 2023) |
| **Weibull 風速分析** | 統計分佈 | 年發電量估算 (AEP) | 統計檢定驗證通過 |
| **統計異常偵測** | Z-score + 分箱比較 | 溫度異常 + 功率曲線偏差 | 綜合健康分數 |

**模型對比框架**：支援一鍵執行多模型對比實驗（NBM vs LSTM vs PatchTST），自動產出論文等級的 LaTeX 對比表格。

### 3. 告警與工單管理

| 功能 | 說明 |
|------|------|
| **告警自動產生** | 分析結果觸發可配置的告警規則 |
| **嚴重程度分級** | info / warning / critical / emergency 四級告警 |
| **外部系統整合** | 標準化 Ingest API，可接收外部 CMS/SCADA 系統告警（自動去重） |
| **工單 Kanban 看板** | 待處理 → 進行中 → 已完成，完整生命週期追蹤 |
| **告警→工單自動建立** | 一鍵從告警建立工單，預填告警資訊 |
| **備註時間線** | 每張工單的處理記錄與時間戳 |

### 4. 知識管理 (RAG)

| 功能 | 說明 |
|------|------|
| **語意搜尋** | BGE-3 嵌入模型 + ChromaDB 向量資料庫 |
| **維護手冊索引** | 上傳風機維護手冊，AI 自動索引建立知識庫 |
| **智慧問答** | 自然語言提問，系統從知識庫中找答案 |
| **MMR 多樣性檢索** | 避免重複結果，提供多角度參考 |

### 5. 虛擬辦公室 (Virtual Office)

獨特的視覺化協作介面，以即時動畫呈現 AI 代理的工作狀態：

| 功能 | 說明 |
|------|------|
| **代理狀態即時顯示** | 42 個 AI 代理的待命/工作中/等待確認/完成/錯誤狀態 |
| **6 個團隊房間** | 指揮中心、資料工程室、模型實驗室、領域知識庫、軟體工程室、研究室 |
| **任務進度面板** | 三欄佈局：代理面板 / 進度日誌 / 即時分析圖表 |
| **3 種辦公室風格** | 像素風格 / 現代風格 / 極簡風格，可切換 |

### 6. 即時推播

| 功能 | 說明 |
|------|------|
| **WebSocket 即時更新** | 分析結果、告警、工單狀態變更即時推送至前端 |
| **告警通知** | 可擴充至 Email / LINE Notify / Webhook |
| **儀表板自動刷新** | 無需手動重新整理，資料即時更新 |

## 技術特色

### 多代理架構 (Multi-Agent System)

系統採用 **6 層代理階層**，模擬真實風場運維團隊的組織結構：

```
指揮層 (wLab:)  ──  專案統籌、任務分派、品質控管
    ↓
資料工程 (wData:)  ──  資料清洗、品質驗證、ETL
AI/ML (wAI:)       ──  模型訓練、實驗追蹤、超參數調整
領域知識 (wDomain:) ──  IEC 標準、風能專業判斷
軟體工程 (wEng:)   ──  系統開發、CI/CD
研究文件 (wRes:)   ──  論文撰寫、文獻搜尋、報告生成
```

- **12 個核心代理** 常駐值班
- **10+ 可聘用代理** 依任務需要動態啟用
- **YAML 驅動配置**，新增代理無需改程式碼

### 技能拆分架構 (Skill-based Architecture)

每個分析能力被封裝為獨立的「技能模組」，可自由組合：

```
資料載入 → 清洗 → 特徵工程 → 模型訓練 → 異常偵測 → 報告生成
   ↑          ↑          ↑          ↑          ↑          ↑
[skill]    [skill]    [skill]    [skill]    [skill]    [skill]
```

- 目前已有 **14 個技能模組**，涵蓋資料處理、ML 訓練、特徵工程、報告生成
- 技能可串聯成自動化管線，無需人工介入
- 新技能自動發現並註冊，即插即用

### 品質保證機制

| 機制 | 說明 |
|------|------|
| **Checkpoint 機制** | 每個步驟設定品質門檻，未達標自動調參重跑 |
| **錯誤重試/降級** | 三種策略：SKIP（跳過）/ FALLBACK（降級）/ ABORT（中止） |
| **實驗追蹤** | JSONL + MLflow 雙軌記錄，每次實驗可追溯 |
| **模型持久化** | 訓練完成的模型自動儲存，可載入再使用 |

## 應用場景

### 場景 1：風場日常監控

```
SCADA 資料 → 自動清洗 → NBM 功率曲線分析 → 異常偵測 → 告警通知
                                                        ↓
                                              工單產生 → 技術員維修
```

**價值**：從「等故障發生才知道」升級為「異常剛出現就預警」。

### 場景 2：預測性維護規劃

```
歷史 SCADA 資料 → 退化趨勢分析 → RUL 剩餘壽命預測 → 維護排程建議
```

**價值**：避免非計畫性停機，降低維修成本 20-30%。

### 場景 3：多模型效能評估

```
風場資料 → ModelBenchmark 一鍵對比 → NBM vs LSTM vs PatchTST
                                        ↓
                              對比報告（含 LaTeX 表格，可直接用於論文）
```

**價值**：快速找出最適合特定風場的模型，支撐學術研究發表。

### 場景 4：外部系統整合

```
外部 CMS 系統 → POST /api/alerts/ingest → WindAI 告警面板
                                              ↓
                                    統一管理多來源告警 → 工單追蹤
```

**價值**：不取代現有 CMS，而是作為統一的 AI 分析與管理層。

### 場景 5：新進工程師培訓

```
工程師提問 → RAG 知識庫搜尋 → 維護手冊 + 歷史案例 → 推薦解決方案
```

**價值**：縮短新手上手時間，不再依賴「老師傅的經驗」。

## 部署方式

### 方案 A：地端部署 (On-Premise)

```
風場機房 / 客戶 IDC
  └── Docker Compose 一鍵部署
      ├── Backend Container (FastAPI + ML Models)
      ├── Frontend Container (React)
      ├── Database (SQLite / PostgreSQL)
      └── ChromaDB (RAG)
```

- 適合：資料安全要求高、網路受限的風場
- 硬體需求：4 核 CPU / 16GB RAM / 100GB SSD（建議）

### 方案 B：雲端部署 (Cloud)

```
AWS / Azure / GCP
  └── Kubernetes Cluster
      ├── 自動擴展
      ├── 多風場多租戶
      └── 全球可存取
```

- 適合：多風場管理、跨國營運

### 方案 C：混合部署 (Hybrid)

- 風場端部署輕量資料收集器
- 雲端執行 AI 分析與管理
- 適合：兼顧資料安全與運算效能
