# 新案例處理能力 — 測試案例規劃

> 目的：驗證系統能有效處理「一個新的案例」——從告警進來、建立工單、處理結案、沉澱為案例、被下次相似問題推薦。
> 排程方式：由 `docs/cursor.md` 的 P1-5 逐切片交給 auto-advance（每次一個 TC 群組），不新增 trigger。
> 規則：只寫 `tests/` 下的自動化測試，不連外、不裝新依賴；注入假 indexer（見 cursor.md TestClient 寫法）。

## 驗收判準（「有效完成」的定義）

1. 流程完整：告警 → 工單 → 結案 → 案例 → 推薦，每步狀態與資料正確銜接
2. 結果可用：相似案例推薦 Top-5 內命中同故障類型的案例
3. 容錯：缺資料 / 重複 / 非法輸入不崩潰，回正確 4xx
4. 效率：單一案例全流程在測試環境 < 2 秒（記錄實測值，不設為失敗門檻）

## 測試案例

| ID | 群組 | 情境 | 預期 |
|----|------|------|------|
| TC-01 | 主流程 | 建立 critical 告警 → 建工單 → 完成工單 | 工單 completed，`/api/cases` +1，案例帶 turbine_id / fault_type |
| TC-02 | 主流程 | 結案後再開同風機同類型新告警 | `/api/cases/similar` Top-5 含 TC-01 案例 |
| TC-03 | 推薦品質 | 植入 3 種故障類型各 3 案例，以各類型查詢 | 每類型 Top-3 命中率 ≥ 80% |
| TC-04 | 冪等 | 同一工單重複結案 | 不產生重複案例 |
| TC-05 | 容錯 | 工單無 turbine_id / 無 notes 結案 | 仍建立案例，欄位為預設值，不拋例外 |
| TC-06 | 容錯 | indexer 失敗（RAG 拋錯） | 結案仍成功，案例保存於 DB，不阻斷 |
| TC-07 | 容錯 | `/api/cases/{id}` 不存在 / `similar` 缺參數 | 404 / 422 |
| TC-08 | 多風場 | 風機歸屬風場後走 TC-01 | `/api/farms/overview`、`/compare` 的告警 / 工單數即時反映 |
| TC-09 | 多風場 | 未歸屬風機的告警 | 不計入任何風場，且不報錯 |
| TC-10 | 效率 | TC-01 全流程計時 | 記錄耗時（< 2 秒為目標） |

## 實作切片（auto-advance 逐次取一）

- 切片 1：TC-01、TC-02、TC-04（主流程 + 冪等）
- 切片 2：TC-05、TC-06、TC-07（容錯）
- 切片 3：TC-03（推薦品質，植入資料集）
- 切片 4：TC-08、TC-09、TC-10（多風場 + 效率）
